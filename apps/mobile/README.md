# @finbuddy/mobile

The FinBuddy app for iOS and Android, built with Expo SDK 57 (React Native, TypeScript, Expo Router). Product context lives in [`/PRODUCT.md`](../../PRODUCT.md).

## Run it

From the repo root:

```bash
npm install      # installs every workspace into the root node_modules
npm run mobile   # expo start
```

Then open the app in Expo Go (scan the QR code), press `a` / `i` for an Android emulator or iOS simulator, or `w` for the web preview.

From this folder the usual Expo commands work too: `npm start`, `npm run typecheck`, `npm run lint`, `npx expo install <package>` (always use this instead of `npm install` for Expo and React Native packages, so versions match the SDK).

## Build an installable Android app (APK)

The app uses native modules (Skia, Reanimated, SecureStore, the date picker), so an installable build needs a native build; Expo Go can only preview it. `eas.json` defines two profiles:

- `preview`: an `.apk` for internal distribution, installable on any Android phone that allows installs from unknown sources.
- `production`: an `.aab` for Google Play (needs a Google Play developer account), with the build number incremented by EAS.

From this folder, with an Expo account:

```bash
npx eas-cli@latest login
npx eas-cli@latest init                                   # first time only: links the project and adds its id to app.json
npx eas-cli@latest build --platform android --profile preview
```

When the build finishes, EAS prints a download link and a QR code for the `.apk`. With Android Studio installed you can also build locally with `npx expo run:android --variant release`.

## Layout

- `src/app/` holds the Expo Router routes. `_layout.tsx` is the root layout (gesture handler root, safe-area provider, stack). Every other file there is a screen.
- Non-route code (components, hooks, stores) goes elsewhere under `src/` and can be imported as `@/...`.
- Domain code (money, ledger, splits, data layer) lives in `packages/shared` and is imported as `@finbuddy/shared`. Metro and TypeScript consume it as source; there is no build step.
- `ios/` and `android/` are not committed. They are generated by Continuous Native Generation (`npx expo prebuild`, `npx expo run:ios|android`, or EAS Build) from `app.json`.

## Configuration notes

- **Placeholder identifiers.** `ios.bundleIdentifier` and `android.package` are both `app.finbuddy.mobile`, and the URL scheme is `finbuddy`. They are placeholders: confirm them before the first store submission, because they cannot change after release.
- **Brand assets.** `assets/brand/` holds the SVG sources (mark, wordmark, lockup, iOS and Android icon layers, splash). The PNGs `app.json` needs are rendered from them with `npm run brand:icons` (sharp, from the repo root) and listed with their hashes in `assets/brand/RASTERS.md`. The readout face lives in `assets/fonts/` (synced from `@expo-google-fonts/mona-sans` with `npm run brand:fonts`); see `src/design/FONTS.md`.
- **Reanimated / worklets.** No `babel.config.js` is needed: `babel-preset-expo` adds `react-native-worklets/plugin` automatically when `react-native-worklets` is installed (Reanimated 4). If a custom `babel.config.js` is ever added, keep `babel-preset-expo` and do not add the plugin a second time.
- **Monorepo.** Expo's Metro config detects the npm workspace automatically, so there is no `metro.config.js`.
- **New Architecture.** SDK 57 always runs on the New Architecture, so `newArchEnabled` is not set.
- `experiments.typedRoutes` and `experiments.reactCompiler` are enabled, as in the SDK 57 default template.
