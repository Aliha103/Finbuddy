# Fonts: the day-one verification and what it decided

DIRECTION.md asks for one check before anything else is built: do the Mona Sans TTFs in
`@expo-google-fonts/mona-sans@0.4.1` carry tabular figures (`tnum`) and the currency glyphs the
sample data and the global claim need? This file records the result and the switch it led to.

## Method

`fontTools` 4.66.1 (Python 3.13, run with `-I`) opened both static weights the app uses and read the
`name`, `cmap`, `GSUB`, `hmtx` and `OS/2` tables:

```
node_modules/@expo-google-fonts/mona-sans/700Bold/MonaSans_700Bold.ttf
node_modules/@expo-google-fonts/mona-sans/600SemiBold/MonaSans_600SemiBold.ttf
```

For `tnum` the script followed the feature's GSUB lookups from each default digit glyph to its
substitute and compared the substitutes' advance widths. For glyph coverage it checked the `cmap`
for every code point in the symbols `Intl.NumberFormat` produces for all 162 `CURRENCY_CODES` across
twenty locales (3,400 renderings), and generated the full code-point list the app ships in
`fontCoverage.ts`.

## Verdict

| Check | MonaSans-Bold (700) | MonaSans-SemiBold (600) |
|---|---|---|
| `tnum` feature present | yes | yes |
| Default digits tabular? | no: 0 = 618, 1 = 420, 2 = 575 … 9 = 629 (per 1000 em) | no: 0 = 617, 1 = 401 … 9 = 622 |
| `tnum` digits tabular? | yes: every digit 600/1000 em | yes: every digit 600/1000 em |
| £ U+00A3, ¥ U+00A5, € U+20AC, $ U+0024 | present | present |
| ₹ U+20B9, ₩ U+20A9 | present | present |
| ₫ U+20AB (VND) | **missing** | **missing** |
| Other `Sc` present | ¢ ¤ ฿ ₪ ₸ ₺ ₿ | same |
| Code points in both weights | 546 | 546 (identical sets) |
| PostScript name (`name` id 6) | `MonaSans-Bold` | `MonaSans-SemiBold` |
| Family / subfamily (`name` 1 / 2) | Mona Sans / Bold | Mona Sans SemiBold / Regular |
| Embedding (`OS/2.fsType`) | 0 (installable) | 0 (installable) |
| Version | 2.000 | 2.000 |

One more property of the tabular set, found in the stage-1 review: under `tnum` Mona Sans substitutes
`zero` with `zero.tf`, a **slashed zero**, so a readout that rolls to "£0.00" shows slashed zeros while
body text keeps the plain zero. It is the face's own design for tabular figures (no stylistic set in
the shipped TTFs gives an unslashed tabular zero), it reads as a gate display rather than as code,
and it is the same on every platform, so it stands as is.

Two consequences:

1. **Tabular figures exist but are not the default.** Mona Sans ships proportional digits and tabular
   ones behind the OpenType `tnum` feature. Every readout therefore sets `fontVariant: ['tabular-nums']`
   (`TABULAR` in `fonts.ts`); React Native maps that to `tnum` on iOS (UIFontDescriptor feature
   settings) and Android (`fontFeatureSettings`), and react-native-web to `font-variant: tabular-nums`.
   Without it the digit columns of the Readout would jitter as values roll.

2. **Some currency symbols are not in the face.** Of the 3,400 Intl renderings, 27 symbol strings use a
   glyph Mona Sans lacks: ₫ (VND), ₱ (PHP), ₽ (RUB), ₴ (UAH), fullwidth ￥ (JPY in `ja-JP`), 元 (CNY in
   `zh-CN`), the Cyrillic ТМТ (TMT), the narrow no-break space in `F CFA` (XOF, French), and the
   Arabic-script abbreviations for AED, BHD, DZD, EGP, IQD, IRR, JOD, KWD, LBP, LYD, MAD, MRU, OMR, QAR,
   SAR, SDG, SYP, TND and YER. The sample data's own currencies (GBP, JPY, USD in `en-*` locales) are
   fully covered.

## The switch

Rather than let the OS stitch a fallback glyph into a Mona Sans figure (mismatched weight, different
baseline, different advance), a readout whose formatted text contains **any** character outside the
546-code-point set switches **as a whole** to the platform face (San Francisco, Roboto, or the web's
system stack) with `fontVariant: ['tabular-nums']`, which those faces honour. The figure keeps the
roll, the tabular columns and the size; it loses the brand voice for that one amount. The decision
is made per readout and per render, so a GBP readout next to a VND readout stays in Mona Sans.

Code: `monaSansCovers(text)` in `fontCoverage.ts` (generated); `readoutFamilyFor(text, family)` and
`readoutWeightFor(family, weight)` in `fonts.ts`; used by `Readout.tsx` and by `Text.tsx` for the
readout roles. The gallery shows a VND readout next to the Mona Sans ones (`/dev/gallery`).

## One family name, three loaders

The readout face reaches the app three ways, and the font is referenced by one name per weight:

| Loader | When | Resolves the family by |
|---|---|---|
| `expo-font` config plugin (`app.json` → `fonts: [...]`) | device builds (development build, EAS) | iOS: the PostScript name; Android: the file name without extension |
| `useFonts(FONT_ASSETS)` (`useAppFonts()` in `fonts.ts`) | Expo Go, and the web preview; a no-op on devices where the plugin already embedded the file | the key passed to `useFonts` |
| web `@font-face` (generated by expo-font on the web) | the Expo web export | the key passed to `useFonts` |

So the files in `assets/fonts/` are named by PostScript name (`MonaSans-Bold.ttf`, `MonaSans-SemiBold.ttf`),
`FONT.readout` is `'MonaSans-Bold'` and `FONT.readoutMedium` is `'MonaSans-SemiBold'`, and every
loader agrees. `scripts/sync-fonts.mjs` (root `npm run brand:fonts`) copies the files from the npm
package so they stay reproducible; `@expo-google-fonts/mona-sans` remains the source of truth and
the provenance. This is why the token names differ from DIRECTION.md's `MonaSans_700Bold` (the npm
package's export names): embedding needs the PostScript parity, and a name that only worked for one
loader would mean a visible font swap on devices.

The splash is held (`SplashScreen.preventAutoHideAsync`) until `useFonts` resolves, with a 1.5 s cap,
so a cold start never flashes the system face on the hero readout.

## Regenerating

```
python3 -m venv .venv && .venv/bin/pip install fonttools
.venv/bin/python -I <font check script> node_modules/@expo-google-fonts/mona-sans/700Bold/MonaSans_700Bold.ttf \
                                        node_modules/@expo-google-fonts/mona-sans/600SemiBold/MonaSans_600SemiBold.ttf
```

The check script reads `name`, `GSUB` (`tnum` lookups), `hmtx` and `cmap`; `fontCoverage.ts` is the
`cmap` intersection of both weights, compressed to ranges. Re-run both whenever the package version
changes, and re-run `npm run brand:fonts`.
